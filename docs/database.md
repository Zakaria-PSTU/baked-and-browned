# Baked & Browned — Database Design
Version: 1.1 | PostgreSQL 17+ | Migrations: `V1__init.sql` … `V7__refund_policy.sql`

## Conventions
- UUID primary keys generated by `gen_random_uuid()` (built into PostgreSQL 13+; the `pgcrypto` line in V1 is retained for fidelity and is harmless where the extension is permitted).
- `TIMESTAMPTZ` for instants; display using `Asia/Dhaka`.
- `NUMERIC(12,2)` for BDT prices; `NUMERIC(14,3)` for ingredient units.
- Foreign keys prevent dangling records; snapshots preserve historical order data.
- Flyway migrations are authoritative; Hibernate `ddl-auto=validate` in every environment (never `update`).
- Migration policy (ADR-0015): `V1__init.sql` is the v1.0 baseline copied verbatim from below. All later changes are new, additive, numbered migrations; an applied migration is never edited. V2–V5 assume no production data exists yet (some add `NOT NULL` columns without defaults to `orders`).
- Copy each SQL block below to `backend/src/main/resources/db/migration/<name>.sql`.
- Seed data in migrations is limited to reference/configuration data (e.g. inactive delivery zones). Migrations never create users or credentials.
- `updated_at` columns are maintained by the `set_updated_at()` trigger (V2), not by application code.

## Relationships
- users 1:N orders, refresh_tokens; refresh_tokens grouped by family_id.
- categories 1:N products.
- products N:M customization_groups through product_customization_groups.
- product_customization_options limits permitted options for each product.
- delivery_zones 1:N orders.
- orders 1:N order_items, payments, order_status_history, refunds; orders 1:1 slot_reservations.
- order_items 1:N order_item_customizations.
- products N:M ingredients through product_ingredients.
- orders 1:N inventory_reservations; ingredients 1:N inventory_movements.
- payments 1:N manual_payment_submissions, refunds, payment_reconciliation_cases.
- orders 1:N notifications (one per outbox event and channel).
- payment_webhook_events and outbox_events support idempotent integrations.
- audit_events records administrative and payment decisions (append-only).

## V1 — baseline (`V1__init.sql`, unchanged from v1.0)
```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TYPE user_role AS ENUM ('CUSTOMER','ADMIN');
CREATE TYPE product_status AS ENUM ('DRAFT','ACTIVE','ARCHIVED');
CREATE TYPE order_status AS ENUM ('PENDING_PAYMENT','CONFIRMED','PREPARING','READY','OUT_FOR_DELIVERY','DELIVERED','CANCELLED','EXPIRED');
CREATE TYPE payment_status AS ENUM ('PENDING','SUCCEEDED','FAILED','CANCELLED','REFUNDED');
CREATE TYPE payment_method AS ENUM ('COD','MANUAL','ONLINE');
CREATE TYPE reservation_status AS ENUM ('HELD','CONFIRMED','RELEASED');

CREATE TABLE users (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 full_name VARCHAR(150) NOT NULL,
 email VARCHAR(255),
 phone VARCHAR(20) NOT NULL UNIQUE,
 password_hash VARCHAR(255) NOT NULL,
 role user_role NOT NULL DEFAULT 'CUSTOMER',
 enabled BOOLEAN NOT NULL DEFAULT TRUE,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CONSTRAINT ck_phone CHECK (phone ~ '^\+8801[3-9][0-9]{8}$')
);
CREATE UNIQUE INDEX uq_users_email_ci ON users(lower(email)) WHERE email IS NOT NULL;

CREATE TABLE refresh_tokens (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
 token_hash CHAR(64) NOT NULL UNIQUE,
 expires_at TIMESTAMPTZ NOT NULL,
 revoked_at TIMESTAMPTZ,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_refresh_user ON refresh_tokens(user_id);

CREATE TABLE categories (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 name VARCHAR(100) NOT NULL UNIQUE,
 slug VARCHAR(120) NOT NULL UNIQUE,
 sort_order INT NOT NULL DEFAULT 0,
 active BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE products (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 category_id UUID NOT NULL REFERENCES categories(id),
 name VARCHAR(180) NOT NULL,
 slug VARCHAR(200) NOT NULL UNIQUE,
 description TEXT,
 base_price NUMERIC(12,2) NOT NULL CHECK(base_price >= 0),
 image_url TEXT,
 status product_status NOT NULL DEFAULT 'DRAFT',
 min_lead_hours INT NOT NULL DEFAULT 24 CHECK(min_lead_hours >= 0),
 production_units INT NOT NULL DEFAULT 1 CHECK(production_units > 0),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_products_category_status ON products(category_id,status);

CREATE TABLE customization_groups (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 name VARCHAR(100) NOT NULL,
 code VARCHAR(80) NOT NULL UNIQUE,
 selection_type VARCHAR(10) NOT NULL CHECK(selection_type IN ('SINGLE','MULTIPLE','TEXT')),
 min_selections INT NOT NULL DEFAULT 0 CHECK(min_selections >= 0),
 max_selections INT NOT NULL DEFAULT 1 CHECK(max_selections >= min_selections),
 CHECK(selection_type <> 'TEXT' OR (min_selections <= 1 AND max_selections = 1))
);
CREATE TABLE customization_options (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 group_id UUID NOT NULL REFERENCES customization_groups(id),
 name VARCHAR(120) NOT NULL,
 price_delta NUMERIC(12,2) NOT NULL DEFAULT 0 CHECK(price_delta >= 0),
 active BOOLEAN NOT NULL DEFAULT TRUE,
 UNIQUE(id,group_id),
 UNIQUE(group_id,name)
);
CREATE TABLE product_customization_groups (
 product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
 group_id UUID NOT NULL REFERENCES customization_groups(id),
 required BOOLEAN NOT NULL DEFAULT FALSE,
 PRIMARY KEY(product_id,group_id)
);
CREATE TABLE product_customization_options (
 product_id UUID NOT NULL,
 group_id UUID NOT NULL,
 option_id UUID NOT NULL,
 PRIMARY KEY(product_id,option_id),
 FOREIGN KEY(product_id,group_id) REFERENCES product_customization_groups(product_id,group_id) ON DELETE CASCADE,
 FOREIGN KEY(option_id,group_id) REFERENCES customization_options(id,group_id)
);

CREATE TABLE delivery_slots (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 start_at TIMESTAMPTZ NOT NULL,
 end_at TIMESTAMPTZ NOT NULL,
 capacity_units INT NOT NULL CHECK(capacity_units > 0),
 reserved_units INT NOT NULL DEFAULT 0 CHECK(reserved_units >= 0),
 active BOOLEAN NOT NULL DEFAULT TRUE,
 CHECK(end_at > start_at),
 CHECK(reserved_units <= capacity_units),
 UNIQUE(start_at,end_at)
);

CREATE TABLE orders (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_number VARCHAR(30) NOT NULL UNIQUE,
 user_id UUID NOT NULL REFERENCES users(id),
 delivery_slot_id UUID NOT NULL REFERENCES delivery_slots(id),
 status order_status NOT NULL DEFAULT 'PENDING_PAYMENT',
 customer_name VARCHAR(150) NOT NULL,
 customer_phone VARCHAR(20) NOT NULL,
 delivery_address TEXT NOT NULL,
 delivery_area VARCHAR(120) NOT NULL,
 delivery_notes TEXT,
 subtotal NUMERIC(12,2) NOT NULL CHECK(subtotal >= 0),
 delivery_fee NUMERIC(12,2) NOT NULL CHECK(delivery_fee >= 0),
 discount_amount NUMERIC(12,2) NOT NULL DEFAULT 0 CHECK(discount_amount >= 0),
 total_amount NUMERIC(12,2) NOT NULL CHECK(total_amount >= 0),
 currency CHAR(3) NOT NULL DEFAULT 'BDT' CHECK(currency = 'BDT'),
 payment_method payment_method NOT NULL,
 idempotency_key UUID NOT NULL,
 expires_at TIMESTAMPTZ,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 UNIQUE(user_id,idempotency_key),
 CHECK(total_amount = subtotal + delivery_fee - discount_amount)
);
CREATE INDEX idx_orders_user_created ON orders(user_id,created_at DESC);
CREATE INDEX idx_orders_status_created ON orders(status,created_at DESC);
CREATE INDEX idx_orders_slot ON orders(delivery_slot_id);

CREATE TABLE order_items (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_id UUID NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
 product_id UUID NOT NULL REFERENCES products(id),
 product_name VARCHAR(180) NOT NULL,
 quantity INT NOT NULL CHECK(quantity > 0),
 unit_base_price NUMERIC(12,2) NOT NULL CHECK(unit_base_price >= 0),
 unit_options_price NUMERIC(12,2) NOT NULL DEFAULT 0,
 unit_price NUMERIC(12,2) NOT NULL CHECK(unit_price >= 0),
 line_total NUMERIC(12,2) NOT NULL CHECK(line_total >= 0),
 production_units INT NOT NULL CHECK(production_units > 0),
 CHECK(unit_price = unit_base_price + unit_options_price),
 CHECK(line_total = unit_price * quantity)
);
CREATE INDEX idx_items_order ON order_items(order_id);

CREATE TABLE order_item_customizations (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_item_id UUID NOT NULL REFERENCES order_items(id) ON DELETE CASCADE,
 group_id UUID NOT NULL REFERENCES customization_groups(id),
 option_id UUID REFERENCES customization_options(id),
 group_name VARCHAR(100) NOT NULL,
 option_name VARCHAR(120),
 text_value VARCHAR(250),
 price_delta NUMERIC(12,2) NOT NULL DEFAULT 0,
 CHECK((option_id IS NOT NULL AND text_value IS NULL) OR (option_id IS NULL AND text_value IS NOT NULL))
);
CREATE INDEX idx_item_customizations ON order_item_customizations(order_item_id);

CREATE TABLE slot_reservations (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_id UUID NOT NULL UNIQUE REFERENCES orders(id),
 slot_id UUID NOT NULL REFERENCES delivery_slots(id),
 reserved_units INT NOT NULL CHECK(reserved_units > 0),
 status reservation_status NOT NULL DEFAULT 'HELD',
 expires_at TIMESTAMPTZ,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_slot_holds_expiry ON slot_reservations(expires_at) WHERE status = 'HELD';

CREATE TABLE ingredients (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 name VARCHAR(120) NOT NULL UNIQUE,
 unit VARCHAR(20) NOT NULL,
 on_hand NUMERIC(14,3) NOT NULL DEFAULT 0 CHECK(on_hand >= 0),
 reserved NUMERIC(14,3) NOT NULL DEFAULT 0 CHECK(reserved >= 0),
 CHECK(reserved <= on_hand)
);
CREATE TABLE product_ingredients (
 product_id UUID NOT NULL REFERENCES products(id),
 ingredient_id UUID NOT NULL REFERENCES ingredients(id),
 quantity_per_unit NUMERIC(14,3) NOT NULL CHECK(quantity_per_unit > 0),
 PRIMARY KEY(product_id,ingredient_id)
);
CREATE TABLE inventory_reservations (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_id UUID NOT NULL REFERENCES orders(id),
 ingredient_id UUID NOT NULL REFERENCES ingredients(id),
 quantity NUMERIC(14,3) NOT NULL CHECK(quantity > 0),
 status reservation_status NOT NULL DEFAULT 'HELD',
 UNIQUE(order_id,ingredient_id)
);

CREATE TABLE payments (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_id UUID NOT NULL REFERENCES orders(id),
 method payment_method NOT NULL,
 provider VARCHAR(60),
 provider_session_id VARCHAR(150),
 provider_transaction_id VARCHAR(150),
 amount NUMERIC(12,2) NOT NULL CHECK(amount >= 0),
 currency CHAR(3) NOT NULL DEFAULT 'BDT' CHECK(currency = 'BDT'),
 status payment_status NOT NULL DEFAULT 'PENDING',
 failure_reason TEXT,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_payments_order ON payments(order_id);
CREATE UNIQUE INDEX uq_payment_transaction ON payments(provider,provider_transaction_id) WHERE provider_transaction_id IS NOT NULL;
CREATE UNIQUE INDEX uq_payment_session ON payments(provider,provider_session_id) WHERE provider_session_id IS NOT NULL;
CREATE UNIQUE INDEX uq_payment_success ON payments(order_id) WHERE status = 'SUCCEEDED';

CREATE TABLE payment_webhook_events (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 provider VARCHAR(60) NOT NULL,
 event_id VARCHAR(180) NOT NULL,
 payment_id UUID REFERENCES payments(id),
 payload JSONB NOT NULL,
 received_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 processed_at TIMESTAMPTZ,
 UNIQUE(provider,event_id)
);
CREATE TABLE outbox_events (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 aggregate_type VARCHAR(80) NOT NULL,
 aggregate_id UUID NOT NULL,
 event_type VARCHAR(120) NOT NULL,
 payload JSONB NOT NULL,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 processed_at TIMESTAMPTZ
);
CREATE INDEX idx_outbox_pending ON outbox_events(created_at) WHERE processed_at IS NULL;
```

## V2 — foundation hardening (`V2__foundation_hardening.sql`)
Refresh-token families for reuse detection (architecture.md, Identity and security), shared `actor_type`, append-only audit log, outbox retry metadata, `updated_at` triggers.
```sql
CREATE TYPE actor_type AS ENUM ('CUSTOMER','ADMIN','SYSTEM','GATEWAY');

-- Refresh token rotation with family-wide revocation on reuse.
ALTER TABLE refresh_tokens
  ADD COLUMN family_id UUID,
  ADD COLUMN replaced_by_id UUID REFERENCES refresh_tokens(id),
  ADD COLUMN used_at TIMESTAMPTZ,
  ADD COLUMN revoke_reason VARCHAR(40);
UPDATE refresh_tokens SET family_id = id WHERE family_id IS NULL;
ALTER TABLE refresh_tokens ALTER COLUMN family_id SET NOT NULL;
CREATE INDEX idx_refresh_family ON refresh_tokens(family_id);

-- Append-only audit log for administrative and payment decisions.
CREATE TABLE audit_events (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 actor_type actor_type NOT NULL,
 actor_user_id UUID REFERENCES users(id),
 action VARCHAR(80) NOT NULL,
 entity_type VARCHAR(80) NOT NULL,
 entity_id UUID,
 reason VARCHAR(500),
 details JSONB NOT NULL DEFAULT '{}'::jsonb,
 trace_id VARCHAR(64),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (actor_type NOT IN ('CUSTOMER','ADMIN') OR actor_user_id IS NOT NULL)
);
CREATE INDEX idx_audit_entity ON audit_events(entity_type, entity_id, created_at DESC);
CREATE INDEX idx_audit_created ON audit_events(created_at DESC);

CREATE FUNCTION reject_mutation() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION '% is append-only', TG_TABLE_NAME;
END $$;
CREATE TRIGGER trg_audit_events_append_only
  BEFORE UPDATE OR DELETE ON audit_events
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();

-- Outbox retry/backoff.
ALTER TABLE outbox_events
  ADD COLUMN attempts INT NOT NULL DEFAULT 0 CHECK (attempts >= 0),
  ADD COLUMN next_attempt_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  ADD COLUMN last_error TEXT;
DROP INDEX idx_outbox_pending;
CREATE INDEX idx_outbox_pending ON outbox_events(next_attempt_at) WHERE processed_at IS NULL;

-- updated_at maintenance.
CREATE FUNCTION set_updated_at() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END $$;
CREATE TRIGGER trg_users_updated_at BEFORE UPDATE ON users
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_products_updated_at BEFORE UPDATE ON products
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_orders_updated_at BEFORE UPDATE ON orders
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
CREATE TRIGGER trg_payments_updated_at BEFORE UPDATE ON payments
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## V4 — ordering policy, history and inventory ledger (`V4__ordering_policy.sql`)
ADR-0008, ADR-0009, ADR-0014. Cancellation cutoffs, idempotency request hash, order number sequence, status history, one-time consumption/release, inventory movements.
```sql
-- Cancellation cutoff per product; strictest cutoff is snapshotted on the order.
ALTER TABLE products
  ADD COLUMN cancellation_cutoff_hours INT NOT NULL DEFAULT 24
    CHECK (cancellation_cutoff_hours BETWEEN 0 AND 720);

-- Product-specific text limit (stricter than the 250-char column).
ALTER TABLE product_customization_groups
  ADD COLUMN text_max_length INT CHECK (text_max_length BETWEEN 1 AND 250);

ALTER TABLE orders
  ADD COLUMN cancellation_deadline TIMESTAMPTZ NOT NULL,
  ADD COLUMN request_hash CHAR(64) NOT NULL;

-- Order numbers: BB-YYYYMMDD-NNNNNN (Dhaka date + this sequence), built by the service.
CREATE SEQUENCE order_number_seq START 1;

CREATE TABLE order_status_history (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 order_id UUID NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
 from_status order_status,
 to_status order_status NOT NULL,
 actor_type actor_type NOT NULL,
 actor_user_id UUID REFERENCES users(id),
 reason VARCHAR(500),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (from_status IS DISTINCT FROM to_status),
 CHECK (actor_type NOT IN ('CUSTOMER','ADMIN') OR actor_user_id IS NOT NULL),
 CONSTRAINT ck_admin_cancel_reason
   CHECK (NOT (to_status = 'CANCELLED' AND actor_type = 'ADMIN') OR reason IS NOT NULL)
);
CREATE INDEX idx_status_history_order ON order_status_history(order_id, created_at);
CREATE TRIGGER trg_status_history_append_only
  BEFORE UPDATE ON order_status_history
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();

-- One-time consumption/release of holds.
ALTER TYPE reservation_status ADD VALUE 'CONSUMED';
ALTER TABLE slot_reservations
  ADD COLUMN released_at TIMESTAMPTZ;
ALTER TABLE inventory_reservations
  ADD COLUMN released_at TIMESTAMPTZ,
  ADD COLUMN consumed_at TIMESTAMPTZ,
  ADD CONSTRAINT ck_inv_release_xor_consume CHECK (released_at IS NULL OR consumed_at IS NULL);
CREATE INDEX idx_inventory_reservations_order ON inventory_reservations(order_id);

ALTER TABLE ingredients
  ADD COLUMN low_stock_threshold NUMERIC(14,3) CHECK (low_stock_threshold >= 0);

CREATE TYPE inventory_movement_type AS ENUM ('INITIAL','ADJUSTMENT','CONSUMPTION');
CREATE TABLE inventory_movements (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 ingredient_id UUID NOT NULL REFERENCES ingredients(id),
 movement_type inventory_movement_type NOT NULL,
 quantity_delta NUMERIC(14,3) NOT NULL CHECK (quantity_delta <> 0),
 on_hand_after NUMERIC(14,3) NOT NULL CHECK (on_hand_after >= 0),
 order_id UUID REFERENCES orders(id),
 actor_type actor_type NOT NULL,
 actor_user_id UUID REFERENCES users(id),
 reason VARCHAR(300),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (movement_type <> 'CONSUMPTION' OR order_id IS NOT NULL),
 CHECK (movement_type <> 'ADJUSTMENT' OR (reason IS NOT NULL AND actor_user_id IS NOT NULL))
);
CREATE INDEX idx_inventory_movements_ingredient ON inventory_movements(ingredient_id, created_at DESC);
CREATE UNIQUE INDEX uq_inventory_consumption_once
  ON inventory_movements(order_id, ingredient_id) WHERE movement_type = 'CONSUMPTION';
CREATE TRIGGER trg_inventory_movements_append_only
  BEFORE UPDATE OR DELETE ON inventory_movements
  FOR EACH ROW EXECUTE FUNCTION reject_mutation();
```
Note: `ALTER TYPE … ADD VALUE` is allowed inside Flyway's transaction on PostgreSQL 12+, but the new value cannot be used in the same migration; V4 does not use it.

## V5 — payments: manual verification, refunds, reconciliation (`V5__payments_manual_refunds.sql`)
ADR-0011, ADR-0012, ADR-0008 (late success).
```sql
-- One "current" payment per order; retries supersede the previous attempt.
ALTER TABLE payments
  ADD COLUMN superseded_at TIMESTAMPTZ,
  ADD COLUMN verified_by UUID REFERENCES users(id),
  ADD COLUMN verified_at TIMESTAMPTZ,
  ADD COLUMN verification_note VARCHAR(500),
  ADD CONSTRAINT ck_payment_verification_complete
    CHECK ((verified_by IS NULL AND verified_at IS NULL)
        OR (verified_by IS NOT NULL AND verified_at IS NOT NULL AND verification_note IS NOT NULL));
CREATE UNIQUE INDEX uq_payment_current ON payments(order_id) WHERE superseded_at IS NULL;

-- Customer-submitted manual payment evidence. Never proof of payment by itself.
CREATE TYPE manual_submission_status AS ENUM ('SUBMITTED','VERIFIED','REJECTED');
CREATE TABLE manual_payment_submissions (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 payment_id UUID NOT NULL REFERENCES payments(id),
 submitted_by UUID NOT NULL REFERENCES users(id),
 provider VARCHAR(20) NOT NULL CHECK (provider IN ('BANK_TRANSFER','BKASH','NAGAD','ROCKET','OTHER')),
 transaction_reference VARCHAR(100) NOT NULL,
 proof_storage_key VARCHAR(255),
 proof_content_type VARCHAR(100),
 proof_size_bytes INT,
 proof_sha256 CHAR(64),
 status manual_submission_status NOT NULL DEFAULT 'SUBMITTED',
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (proof_storage_key IS NULL
     OR (proof_content_type IN ('image/jpeg','image/png','application/pdf')
         AND proof_size_bytes BETWEEN 1 AND 5242880
         AND proof_sha256 IS NOT NULL))
);
CREATE INDEX idx_manual_submissions_payment ON manual_payment_submissions(payment_id);
CREATE UNIQUE INDEX uq_manual_submission_open
  ON manual_payment_submissions(payment_id) WHERE status = 'SUBMITTED';
-- A transaction reference cannot back two payments unless rejected.
CREATE UNIQUE INDEX uq_manual_reference
  ON manual_payment_submissions(provider, transaction_reference) WHERE status <> 'REJECTED';

-- Refund workflow: REQUESTED -> APPROVED/REJECTED -> COMPLETED (full refunds only in MVP).
CREATE TYPE refund_status AS ENUM ('REQUESTED','APPROVED','REJECTED','COMPLETED');
CREATE TABLE refunds (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 payment_id UUID NOT NULL REFERENCES payments(id),
 order_id UUID NOT NULL REFERENCES orders(id),
 amount NUMERIC(12,2) NOT NULL CHECK (amount > 0),
 currency CHAR(3) NOT NULL DEFAULT 'BDT' CHECK (currency = 'BDT'),
 status refund_status NOT NULL DEFAULT 'REQUESTED',
 request_reason VARCHAR(500) NOT NULL,
 requested_by_type actor_type NOT NULL,
 requested_by UUID REFERENCES users(id),
 decided_by UUID REFERENCES users(id),
 decided_at TIMESTAMPTZ,
 decision_note VARCHAR(500),
 external_reference VARCHAR(150),
 completed_at TIMESTAMPTZ,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (status = 'REQUESTED'
     OR (decided_by IS NOT NULL AND decided_at IS NOT NULL AND decision_note IS NOT NULL)),
 CHECK (status <> 'COMPLETED' OR (external_reference IS NOT NULL AND completed_at IS NOT NULL))
);
CREATE UNIQUE INDEX uq_refund_active_per_payment
  ON refunds(payment_id) WHERE status <> 'REJECTED';
CREATE INDEX idx_refunds_status ON refunds(status, created_at);
CREATE TRIGGER trg_refunds_updated_at BEFORE UPDATE ON refunds
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- Reconciliation for late successes, amount mismatches and ambiguous outcomes.
CREATE TYPE reconciliation_case_type AS ENUM ('LATE_SUCCESS','AMOUNT_MISMATCH','AMBIGUOUS_STATUS');
CREATE TYPE reconciliation_case_status AS ENUM ('OPEN','RESOLVED');
CREATE TABLE payment_reconciliation_cases (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 payment_id UUID NOT NULL REFERENCES payments(id),
 order_id UUID NOT NULL REFERENCES orders(id),
 case_type reconciliation_case_type NOT NULL,
 status reconciliation_case_status NOT NULL DEFAULT 'OPEN',
 details JSONB NOT NULL DEFAULT '{}'::jsonb,
 resolution VARCHAR(20) CHECK (resolution IN ('REINSTATED','REFUND_REQUESTED','NO_ACTION')),
 resolved_by UUID REFERENCES users(id),
 resolved_at TIMESTAMPTZ,
 resolution_note VARCHAR(500),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 CHECK (status = 'OPEN'
     OR (resolution IS NOT NULL AND resolved_by IS NOT NULL
         AND resolved_at IS NOT NULL AND resolution_note IS NOT NULL))
);
CREATE UNIQUE INDEX uq_reconciliation_open
  ON payment_reconciliation_cases(payment_id, case_type) WHERE status = 'OPEN';
```

## V6 — notifications (`V6__notifications.sql`)
Business rules, Notifications: retryable and idempotent customer notices sent from the outbox after commit.
```sql
-- Customer notices delivered from outbox events: one row per event and channel, so a redelivered
-- event never sends twice. The body is fixed at the first attempt and resent unchanged on retries.
CREATE TYPE notification_channel AS ENUM ('SMS','EMAIL');
CREATE TYPE notification_status AS ENUM ('PENDING','SENT');
CREATE TABLE notifications (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 outbox_event_id UUID NOT NULL,
 order_id UUID NOT NULL REFERENCES orders(id),
 user_id UUID NOT NULL REFERENCES users(id),
```

## V7 — refund policy (`V7__refund_policy.sql`)
ADR-0017: partial refunds, second approver, refund-completed notice.
```sql
-- Partial refunds: several refunds per payment, at most one open (REQUESTED or APPROVED) at a time.
-- The service keeps the sum of non-rejected refunds within the payment amount under the payment lock.
DROP INDEX uq_refund_active_per_payment;
CREATE UNIQUE INDEX uq_refund_open_per_payment
  ON refunds(payment_id) WHERE status IN ('REQUESTED','APPROVED');
-- Second approver: whoever requested a refund never approves it.
ALTER TABLE refunds
  ADD CONSTRAINT ck_refund_second_approver
    CHECK (status NOT IN ('APPROVED','COMPLETED') OR requested_by IS NULL OR decided_by <> requested_by);
-- Customer notice when a refund has been sent.
ALTER TABLE notifications DROP CONSTRAINT notifications_kind_check;
ALTER TABLE notifications
  ADD CONSTRAINT notifications_kind_check
    CHECK (kind IN ('ORDER_RECEIVED','ORDER_CONFIRMED','ORDER_DISPATCHED','ORDER_CANCELLED','ORDER_EXPIRED',
                    'REFUND_COMPLETED'));
-- Refunds never exceed the payment: non-rejected refunds together stay within its amount. The payment
-- row is locked, so concurrent inserts or updates for one payment are checked one at a time.
CREATE FUNCTION check_refund_total() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
  paid NUMERIC(12,2);
  taken NUMERIC(12,2);
BEGIN
  IF NEW.status = 'REJECTED' THEN
    RETURN NEW;
  END IF;
  SELECT amount INTO paid FROM payments WHERE id = NEW.payment_id FOR UPDATE;
  SELECT coalesce(sum(amount), 0) INTO taken FROM refunds
   WHERE payment_id = NEW.payment_id AND status <> 'REJECTED' AND id <> NEW.id;
  IF taken + NEW.amount > paid THEN
    RAISE EXCEPTION 'ck_refund_within_payment: refunds of payment % would exceed its amount', NEW.payment_id
      USING ERRCODE = 'check_violation', CONSTRAINT = 'ck_refund_within_payment';
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER trg_refunds_within_payment
  BEFORE INSERT OR UPDATE OF amount, status, payment_id ON refunds
  FOR EACH ROW EXECUTE FUNCTION check_refund_total();
```

## Service-enforced invariants not fully captured by DDL
- Refund requests name at most what is left of the payment (amount minus completed refunds); the V7 trigger is the backstop for the total.
- Selected option belongs to the product and correct group; effective selection count rule (business-rules.md) and product-specific text limit.
- Order subtotal equals sum of its item lines; item options total equals sum of option snapshots.
- Order `delivery_fee`/`delivery_area` equal the zone's fee/name at placement; zone was eligible (active, fee set, minimum met).
- `cancellation_deadline = slot.start_at − max(item product cancellation_cutoff_hours)` at placement.
- `request_hash` is SHA-256 of the canonicalized `PlaceOrderRequest` minus `idempotencyKey`.
- Slot reservation points to the same slot as its order.
- Inventory reservation quantities match the product recipe requirements.
- Only valid state transitions (architecture.md), each with exactly one `order_status_history` row; one-time release/consumption of holds.
- A successful payment amount/currency matches the order; a refund amount equals its payment amount.
- Manual payment SUCCEEDED only with `verified_by` an ADMIN; a submission alone never changes payment status.
- No slot/ingredient overselling under concurrency.

```sql
UPDATE delivery_slots
SET reserved_units = reserved_units + :units
WHERE id = :slot_id AND active = TRUE
  AND reserved_units + :units <= capacity_units
RETURNING id;

UPDATE ingredients
SET reserved = reserved + :quantity
WHERE id = :ingredient_id
```
